
AI Prompt Specification: Gamified Coding Telemetry Platform (Elixir/Phoenix)

Context & Core Inspiration:
We are building a highly real-time, gamified coding telemetry system using a pure Elixir and Phoenix LiveView architecture. The platform merges the programmatic telemetry ingestion concepts of Code::Stats (receiving development metrics via IDE extensions) with the retro gameplay, status tracking, and password mechanics of Faxanadu (NES).
System Design Rules to Re-Initialize:
1. Multi-Class Specialization: Users have a global aggregate account status, but each programming language has its own independent rank, level trajectory, and title generation schema (tracked via a user_languages table).
2. Procedural Rank Generation (The King): Ranks are not hardcoded. A domain logic module (GameEngine.King) evaluates XP milestones exponentially and dynamically synthesizes unique titles based on the user's current track proficiency (e.g., "Level 6 Knight-Compiler: The Asynchronous Elixir Supervisor").
3. Mantra Snapshot Saves (The Priest): State saving mirrors old password-save mechanics. A UUID-keyed mantras table stores an immutable snapshot of all language tracks, levels, and companions. The Priest only locks down a save state if all language tracks are fully caught up with the King's blessings (no unspent level-ups). If valid, it can completely restore a developer's profile via atomic database transactions.
4. AI Companions: When developers utilize AI tools, telemetry triggers Companion XP instead of language XP. Companions exist as distinct party members (companions table) with custom nicknames, independent levels, and procedurally generated robotic archetypes (e.g., "Level 4 Subroutine: Generative-Golem Neural Oracle").
5. Anonymized Project Sessions & Teams: A global Elixir Registry and DynamicSupervisor automatically maps developers into real-time cooperative party rooms (PartyRoom GenServers) based on their workspace. To protect intellectual property, local project file-paths are cryptographically hashed using a server salt into an un-hashable runic signature (e.g., REALM-4aef81).
6. 1% Cooperative Party Multiplier: The orchestrator inspects the live memory size of the target PartyRoom GenServer. For every additional coworker concurrently writing code inside that workspace signature, a compounding 1% bonus XP multiplier is injected into the telemetry stream (capped at 25%).
7. Ambient Background Loop: A RandomWorldWorker GenServer runs silently on background runtime threads, waking up at random intervals to simulate a living environment by randomly executing rogue King promotions or mysterious background Priest Mantra saves to active developers in the wild.
8. Pure LiveView Architecture: The system entirely completely bypasses GraphQL/API client frameworks. Real-time updates, terminal logs, scoreboards, and profile cards are pushed directly over WebSockets via single-codebase LiveView modules.

🧠 2. Core Game Logic Components (lib/game_engine/)


A. The King Engine (king.ex)

• XP Curves: \(\text{level} = \lfloor(\text{xp} / 1000)^{(1 / 1.5)}\rfloor\).
• Asynchronous Coronation: Users accumulate raw XP in the background but do not update their levels or titles until they explicitly visit the King (or trigger a random world encounter).
• Procedural Rank Generation: Dynamically synthesizes a rank based on their highest programming language and level tier (e.g., "Level 7 Knight-Compiler: The Asynchronous Elixir Supervisor").
elixir
defmodule GameEngine.King do
  @xp_base 1000
  @xp_factor 1.5

  def calculate_true_level(xp) when xp < @xp_base, do: 1
  def calculate_true_level(xp), do: Float.floor(:math.pow(xp / @xp_base, 1 / @xp_factor)) |> trunc()

  def visit_king(user_language_records) do
    Enum.reduce(user_language_records, [], fn user_lang, acc ->
      true_lvl = calculate_true_level(user_lang.total_xp)
      if true_lvl > user_lang.current_level do
        new_title = generate_language_rank(user_lang.language, true_lvl)
        [{user_lang.id, true_lvl, new_title} | acc]
      else
        acc
      end
    end)
  end

  defp generate_language_rank(lang, level) do
    tier = cond do
      level in 1..5 -> "Aspirant"
      level in 6..10 -> "Knight-Compiler"
      true -> "Overlord"
    end
    "Level #{level} #{tier}: Optimized #{String.capitalize(lang)} Artisan"
  end
end

B. The Checkpoint Guard (priest.ex & priest_restore.ex)

• The Rule: The Priest will refuse to grant a Mantra save state if any language or AI companion has unspent XP that requires a visit to the King. Ranks must be fully up-to-date.
• Timeline Rollbacks: Reconstructing a Mantra completely wipes the user's active session stats and rolls their profile, languages, and companion datasets back to the exact snapshot recorded inside the UUID transaction.

📡 3. Real-Time Telemetry & Team Multiplexing


A. Anonymized Party Rooms (project_crypt.ex & party_room.ex)

• Path Hashing: Hashes absolute project repository file paths with a cryptographic salt into a short string (e.g., REALM-4aef81) to completely hide commercial codebase directories.
• Concurrently Synced Rooms: A dynamic, registry-backed GenServer structure handles automated user check-ins. If developers are editing within the same project workspace signature, they are placed in a cooperative dungeon room together.

B. The 1% Cooperative Modifiers (orchestrator.ex)

• Cooperative Buffing: Telemetry ingestion monitors the active user map of the PartyRoom GenServer. For every extra developer concurrently typing in the matching workspace signature, a compounding 1% bonus XP is tacked onto the incoming payload array (e.g., 3 active developers = a 1.02 multiplier curve).
elixir
defmodule GameEngine.Orchestrator do
  @base_multiplier 1.0
  @per_member_bonus 0.01  # 🌟 1% bonus multiplier per developer in party room
  @max_multiplier 1.25

  def ingest_with_multipliers(user_id, language, raw_xp, hashed_project) do
    party_size = case Registry.lookup(CodeStats.ProjectRegistry, hashed_project) do
      [{pid, _}] -> map_size(:sys.get_state(pid).active_members)
      [] -> 1
    end

    multiplier = min(@base_multiplier + ((party_size - 1) * @per_member_bonus), @max_multiplier)
    final_xp = round(raw_xp * multiplier)

  end
end
